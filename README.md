### UI/UX 改造配套提示词

```markdown
# 任务：使用专业 UI/UX Skills 优化现有 Web 项目

请对当前项目已经存在的 Web 界面进行全面的 UI/UX 分析、设计和改造。

**核心目标：**

在不影响现有业务功能的前提下，显著提升整个 Web 界面的视觉品质、布局合理性、操作体验和设计一致性。

我希望最终界面具有现代、专业、精致、简洁的视觉效果，而不是常见的、千篇一律的 AI 生成网页。

## 一、充分利用已安装的 Skills

请根据实际任务合理组合以下三个 Skills：

- `$ui-ux-pro-max`：负责设计系统、风格选择、配色、字体、组件规范及 UX 设计建议。
- `$frontend-design`：负责提升整体视觉品质、布局设计、排版、视觉层级与设计辨识度。
- `$web-design-guidelines`：在修改完成后进行独立的界面规范、交互体验和可访问性审查。

不要机械地让三个 Skills 同时处理所有任务，而应根据各自优势分阶段使用。

## 二、分析现有项目

开始修改前，请先：

1. 阅读现有前端代码，了解项目的技术栈、页面结构、组件和样式组织方式。
2. 理解网页的真实用途、主要操作流程和用户需求。
3. 找出现有界面在布局、配色、字体、间距、信息层级、组件一致性和交互体验方面的问题。
4. 识别现有的业务功能、API 调用及必须保留的交互行为。
5. 检查项目中是否存在已有设计规范、组件库或用户自定义主题，优先考虑兼容。

请基于项目自身的用途选择设计方向，不要盲目套用固定模板。

## 三、设计与实际改造

结合 UI/UX Pro Max 和 Frontend Design：

1. 制定统一的设计系统，包括颜色、字体、间距、圆角、阴影、图标和组件状态。
2. 重新审视页面布局、导航结构、内容分区及信息呈现方式。
3. 优化按钮、表单、表格、卡片、弹窗、通知、状态标签等实际存在的组件。
4. 改善重要操作的可发现性、错误提示、加载状态及空数据状态。
5. 合理处理内容密度，避免无意义的大面积留白，以及过度拥挤。
6. 确保页面具有良好的视觉层级，让用户能够迅速找到重要信息和主要操作。
7. 根据项目实际需求支持桌面端和移动端响应式布局。
8. 注重细节与一致性，避免随意堆叠设计效果。

可以大胆改善页面结构和视觉设计，但所有改变都应服务于实际使用体验。

## 四、设计原则

- 现代、简洁、专业、有辨识度。
- 功能优先，审美与实用性兼顾。
- 视觉语言统一，组件行为一致。
- 避免过度渐变、花哨动画、滥用玻璃拟态及无意义装饰。
- 不强行使用某一种流行设计风格。
- 不因为追求美观而牺牲信息密度和操作效率。
- 优先采用成熟、稳定、便于维护的实现方式。

## 五、严格保护现有功能

这是一个已经存在并可能正在使用的项目，不是新项目。

必须遵守：

1. 不删除、不隐藏任何现有业务功能或重要操作入口。
2. 不随意修改后端代码、API 协议、数据库结构和核心业务逻辑。
3. 保持现有路由、数据处理和用户操作行为兼容。
4. 尽可能沿用当前项目的技术栈、依赖和组件体系。
5. 不为单纯改善视觉效果引入大量额外依赖。
6. 修改前检查现有文件和 Git 工作区状态，保护用户尚未提交的改动。
7. 需要涉及业务逻辑或破坏性变更时，应先说明必要性并征求确认。
8. 不擅自修改生产环境配置或重启正在运行的正式服务。

## 六、实际运行与验证

不要只根据代码判断页面是否美观。

如果当前环境具备浏览器测试能力，请：

1. 使用项目现有方式启动测试环境。
2. 实际打开相关网页，查看渲染效果。
3. 对主要页面进行桌面端和移动端截图检查。
4. 检查字体、排版、颜色、对齐、溢出、滚动及响应式问题。
5. 测试关键按钮、表单、导航及弹窗的实际交互。
6. 根据发现的问题继续修改，并再次验证。

如果无法使用浏览器，应执行可用的构建、静态检查及测试，并明确说明哪些视觉效果未能实际验证。

## 七、独立审查与修复

设计和开发完成后，再使用 `$web-design-guidelines`：

1. 审查本次修改涉及的前端页面和组件。
2. 检查界面规范、可访问性、操作反馈与交互问题。
3. 根据严重程度处理发现的问题。
4. 修复问题时避免破坏已完成的视觉设计和现有功能。
5. 执行必要的构建和回归验证。

不要将审查结果仅作为报告输出，应尽可能完成实际修复。

## 八、执行方式与最终交付

请自主完成以下流程：

分析现状 → 制定设计方案 → 修改现有代码 → 实际验证 → 独立审查 → 修复问题 → 最终检查。

不要停留在提出建议或生成设计稿的阶段，应真正完成现有代码的改造。

一般性的视觉和布局决策可以自行判断，无须逐项询问我；只有涉及重要功能取舍、较大范围重构或破坏性操作时才需要确认。

最终请用简体中文简要说明：

1. 原有 UI/UX 的主要问题。
2. 采用了什么设计方向及原因。
3. 实际修改了哪些页面和组件。
4. 三个 Skills 分别发挥了什么作用。
5. 进行了哪些测试与审查，结果如何。
6. 是否存在尚未解决的问题。
7. 如何查看改造后的网页。

**最重要的是：请将当前项目当作一个真实、需要长期维护的产品来优化，而不是为了展示视觉效果而重新制作一个演示网站。**
```
